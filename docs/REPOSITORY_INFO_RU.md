# Оформление репозитория GitHub

## Рекомендуемый репозиторий

`LeoBanned/crocodile-gena-studio-releases`

Лучше оформить уже существующий репозиторий релизов и не создавать второй: текущая версия приложения проверяет обновления именно в нём. Содержимое подготовленной папки следует поместить в ветку `main`, а установщики продолжить прикреплять к Releases.

Если позже понадобится имя `crocodile-gena-studio`, сначала обновите адрес проверки обновлений в самой программе и выпустите переходную версию. После этого репозиторий можно переименовать.

## Рекомендуемые настройки

- включить **Issues**;
- включить **Private vulnerability reporting**;
- показывать **Releases** в правой колонке;
- отключить **Wiki**, пока для неё нет отдельного материала;
- не загружать установщики в ветку репозитория — прикреплять их к Release;
- не включать API-ключи, `.env`, локальные логи и сборочные каталоги.

Пошаговая публикация описана в [PUBLISHING_GUIDE_RU.md](PUBLISHING_GUIDE_RU.md).

## Текст первого релиза

**Заголовок:** `Crocodile Gena Studio 4.0.3`

**Краткое описание:**

> Публичный релиз Crocodile Gena Studio 4.0.3 — модульной игровой утилиты для Windows. В версии доступны Online Fix, менеджер сохранений, управление игровыми компонентами, CrocLua, понятные статусы операций и автоматическая проверка обновлений.

**Перед публикацией Release:**

1. Протестировать установку на чистом компьютере или виртуальной машине.
2. Проверить версию в интерфейсе, имени установщика и метаданных файла.
3. Проверить запуск ярлыка и прямой запуск `.exe`.
4. Убедиться, что автообновление указывает на этот Release.
5. Просканировать установщик и сохранить его SHA-256.
6. Добавить в описание размер файла и SHA-256.
